Wireframe: Multi-block working hours + deferred apply

Low-fi whiteboard sketch. Story 2, on the existing /provider → Weekly working hours section (AppShell chrome above it is unchanged and omitted here). Extends the current Mon–Sun checkbox rows; does NOT redesign the page.

Each enabled day = a stack of block rows (start / end time inputs, same <input type="time"> as today) + a per-block "✕ Remove" + one "+ Add block" per day. Unlimited blocks. Unchecking the day keeps today's behaviour ("Unavailable"). Removing the LAST block ≙ unchecking the day. New block defaults: 1h after the previous block's end (or 09:00–17:00 if first). Success message = existing "Working hours saved." line.

Errors are per-day, inline under the offending blocks (extends today's per-row role="alert" pattern); the offending time inputs are highlighted. Save is blocked; focus jumps to the first invalid input. Note: a 12:00 end + 13:00 start IS valid (exactly 1h gap); 12:00 end + 12:00 start (touching) is NOT. No auto-merge, no auto-fix — the provider edits the times themselves.

Same shared alertdialog shell as today's CollisionWarningModal (focus trap, ×/Esc/"Go back" = cancel, radio resolutions) — the "keep new hours as flagged exceptions" radio is REPLACED by "Apply from a future date" with an embedded <input type="date"> (same date pattern BlockedTimeSection uses). Date defaults to the earliest safe date; min = earliest safe date so earlier dates can't be picked; any later date is allowed. Confirm button label echoes the chosen date. Choosing "Apply from…" saves NOTHING immediately — it schedules a pending change (Panel 4).

Banner sits at the top of the section, above the CURRENT (live) hours — the form always shows what is live today. "Show full pending schedule" expands a read-only Mon–Sun summary of the pending hours inline. Edit pending change loads the pending hours into the form for editing; saving re-runs the same collision check → dialog flow and REPLACES the pending change (one pending change at a time). Cancel pending change asks a one-line confirm, then discards it; current hours stay untouched. On the effective date the switch happens server-side; banner disappears and the form shows the new hours.
